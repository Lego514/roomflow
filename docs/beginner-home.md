# 室友首頁與一鍵連線檢查

`npm start` 後開啟終端顯示的本機網址。首頁供日常操作；`/monitor.html` 保留連線紀錄、事件與演練回放，`/lab.html` 保留原有模型與 Linux 實驗證據。

## 使用需求與路由器生效狀態

首頁提供「打遊戲／開會」、「一般使用」、「我可以讓路」。目前只在本瀏覽器保存選擇與期限，到期恢復一般使用；**未連接家中路由器，也未套用優先權或公平排隊**。這個選擇不是登入身分／裝置綁定，也不會呼叫原有模型 session 冒充家用網路控制。原有模型計時示範仍在進階實驗頁。

下一階段需要一個經實測支援的路由器／gateway、裝置與使用者綁定，以及讀回確認、期限恢復和多使用者公平規則。首頁目前不能讓室友從其他電腦直接連入：HTTP 服務仍僅監聽 localhost。

## 第一次設定與裝置名稱

首頁提供「第一次設定／管理者協助」：可替執行 RoomFlow 的電腦取友善名稱，並選填路由器品牌、型號及自述管理權。沒有設備資料也能先保存名稱。準備資料保存在本機 `data/home-setup.json`，可重新開啟表單修改；不輸入或保存路由器密碼。

`GET /api/home-setup` 讀取準備資料；`POST /api/home-setup` 僅接受 `deviceAlias`、`routerBrand`、`routerModel` 與 `managementAccess`。名稱與型號只是資料，不能把 capability 變成已連接或已綁定。任何 `routerConnected`／`deviceBound` 等權限欄位會被拒絕。資料損壞會顯示無法讀取，不冒充設定完成；明確重新儲存可修復。

設定進度分成「本機命名」、「路由器資料已提供但待驗證」、「管理者連接與設備綁定待完成」。多人同級公平、只改自己的設備、限時恢復均為待實作的準備規則，畫面不顯示虛構的室友人數或已套用狀態。可複製準備清單給管理者，自行決定是否傳送。

## 檢查後的下一步與比較

取得有效結果後，可選「我接好網路線了」、「已暫停下載」、「已靠近路由器」再檢查，或用「維持現況，再量一次比較」觀察重複量測的變化。這些條件由使用者表示，RoomFlow 不會代為變更網路，也不會自動證實改動已完成。

比較必須配對到該次按鈕啟動的新工作；其他瀏覽器先前已啟動的檢查、失敗工作、時間相同或間隔超過 30 分鐘的結果不能當作本次比較。比較基準過期超過 15 分鐘時，需先取得新結果。缺少的數值保留未知，不當作零延遲或改善。

畫面顯示前後時間、使用者表示的條件、各層 p95 與探測未成功次數；最多 6 份比較保存在這個瀏覽器，重開仍能讀取。比較紀錄與本機 SQLite 量測歷史是不同儲存範圍，清除瀏覽器資料會移除比較。這些少量前後觀察不能直接建立原因或證明 LOL／會議改善。

「複製檢查摘要」及「複製這份比較摘要」產生繁中／英文純文字，僅含固定的探測欄位與限制，排除 IP、SSID、主機名稱及原始錯誤。若瀏覽器無法直接複製，會提供可選取的文字框手動複製；不會自動對外傳送。

## 一鍵輕量檢查

- `GET /api/quick-check` 只讀最新工作，`GET /api/quick-check/:id` 只讀指定工作。
- `POST /api/quick-check` 接受空 JSON 物件 `{}`，啟動固定輕量探測。無可自訂命令、檔案或目標。重複啟動回傳目前工作，不額外產生同時探測。
- 使用 Python `homenet.check.run_check(count=3)` 觀察 gateway、外部 TCP、DNS 與選定服務的 TCP 連線；不做下載／上傳壓力測試。執行有總期限，逾時呈現未完成，不以舊資料替代本次成功。
- **檢查範圍是執行 RoomFlow 的主機**。從別的裝置開啟網頁不能把結果當成那台裝置自身的 Wi-Fi／網路品質。
- 少量探測不能保證 LOL 或會議正常；探測失敗比例不是遊戲／會議的媒體丟包率。單次觀察不確定根本原因，也不直接確認既有事件已恢復。
- 詳細結果顯示每層最慢目標的單次 p95 與嘗試／失敗次數；此 p95 不是合併所有目標樣本後重算。數據不足保持未知。
- 歷史寫入使用現有 SQLite／事件匯出流程。有效測量與「歷史是否儲存」分開呈現；不匯出 SSID、MAC、IP、主機名稱或原始系統錯誤。

需要可執行的 Python 3；可用 `ROOMFLOW_PYTHON` 指定 Python 執行檔路徑（不是含參數的命令字串）。本機防火牆／缺少執行環境／網路限制可能讓檢查失敗，介面會提供重試而不顯示假成功。
